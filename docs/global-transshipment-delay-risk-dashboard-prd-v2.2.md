## 2. 제품 목적과 사용자

### 문제 정의

#### 현재 상황

- 사내 기존 물류 대시보드는 최종 도착 ETA 지연 여부를 중심으로 설계되어 있다.
- ETA 지연 결과는 확인할 수 있지만, 지연이 어느 환적항과 TS 단계에서 시작되었는지 바로 파악하기 어렵다.
- 환적 대기 정보와 원인은 Cello 시스템, 선사 메일, 항만 공지, 뉴스와 외부 사이트에 분산되어 있다.
- 담당자는 여러 자료를 수작업으로 비교하여 지연 원인과 영향 물동을 판단하고 있다.

#### 환경 변화

- 전쟁과 지정학적 긴장으로 선박 우회, 항로 변경과 특정 항만 물량 집중이 반복되고 있다.
- 과거에는 환적 지연이 잦지 않았던 항만에서도 갑작스러운 혼잡과 장기 대기가 발생한다.
- 기상, 파업, 운하 운영 제한과 선사 스케줄 변경도 다른 항만으로 위험을 빠르게 전파한다.
- 따라서 과거 혼잡 이력이나 기존 위험 항만 목록만으로는 신규 환적 위험을 충분히 감지할 수 없다.

#### 업무상 문제

- 7일 이상 환적 대기 물량을 항만·TS 단계별로 조기에 식별하기 어렵다.
- 한 Shipment가 여러 환적항을 거치면 어느 TS에서 위험이 발생했는지 구분하기 어렵다.
- 외부 이벤트와 실제·예정 환적 물동의 연관성을 수작업으로 판단해야 한다.
- 위험을 확인한 후에도 대체 환적항, 다음 모선과 긴급운송 대안을 한 기준으로 비교하기 어렵다.
- 조치 후 위험이 실제로 감소했는지 일관된 기준으로 측정하기 어렵다.

따라서 최종 ETA 결과만 보여주는 관제를 보완하여, 환적 지연의 `현황 → 원인 → 영향물동 → 대응 → 성과`를 연결하는 환적 중심 대시보드가 필요하다.

### 제품 목표

1. 실제 또는 예상 환적 대기가 7일 이상인 B/L을 조기에 탐지한다.
2. 위험 환적항과 TS1·TS2·TS3 단계를 구분한다.
3. 생산법인·항만·B/L·Container 기준으로 위험을 조회한다.
4. 외부 이벤트와 영향 Shipment를 자동 매칭하고 근거를 제공한다.
5. 대응 아이디어를 비교하고 7일 전 대비 오늘의 결과를 측정한다.

### 사용자

| 사용자 | 주요 목적 |
|---|---|
| 글로벌 물류 관제 담당자 | 위험 확인, 원인 파악, 담당자 배정 |
| 생산법인 SCM 담당자 | 자사 물량과 대응상태 확인 |
| 물류 관리자 | 대응 아이디어와 우선순위 확인 |
| 경영진 | 위험 규모와 개선 성과 확인 |
| 데이터 관리자 | 데이터·API·예측 품질 관리 |

핵심 업무 흐름은 `관제 → 이벤트 → 시나리오 → 성과`다. 탭을 이동해도 전역 필터와 선택 Shipment·항만·이벤트 문맥을 유지한다.

### 비목표

- 예약·운송 자동 변경
- 뉴스만을 근거로 한 지연 판정
- 실제 운송비 정산·결제
- 원천 Cello 시스템 데이터 수정
- 데모 수치를 실제 운영 실적으로 사용하는 행위

## 3. 데이터와 위험 정책

### 데이터 단위

- Shipment는 하나 이상의 B/L과 Container를 가질 수 있다.
- Shipment는 TS1, TS2, TS3 등 여러 환적 단계를 가질 수 있다.
- 각 TS는 순서, 항만, 상태와 실제·예측 대기일수를 가진다.
- 예정 TS도 Alert 대상이며 현재·완료 TS와 구분한다.
- Shipment와 선박은 유효기간을 가진 MMSI 이력으로 연결한다.

### 위험등급

| 등급 | 환적 대기일수 | KPI |
|---|---:|---|
| 정상 | 7일 미만 | PASS |
| Medium | 7일 이상 14일 미만 | FAIL |
| High | 14일 이상 21일 미만 | FAIL |
| Critical | 21일 이상 | FAIL |

경계값 7.0일, 14.0일, 21.0일부터 각각 상위 위험구간에 포함한다.

### 집계 규칙

- `KPI FAIL = Medium + High + Critical`로 계산한다.
- KPI 카드의 기본 단위는 고유 B/L이다.
- 한 B/L에 여러 TS가 있으면 필터 범위에서 가장 높은 등급을 사용한다.
- 동일 Container가 여러 TS에 있어도 Container KPI에서는 한 번만 집계한다.
- 현재·완료 TS는 실제값, 예정 TS는 예측값을 사용한다.
- 결측값을 0으로 바꾸지 않고 산출 대기 또는 비교 불가로 표시한다.

## 4. 전역 필터

### 필터 항목

- 생산법인
- 환적항
- 환적 대기 일수
  - 7일 미만
  - 7일 이상 14일 미만
  - 14일 이상 21일 미만
  - 21일 이상
- B/L 번호
- Container 번호

### 필터 논리

1. 모든 필터는 복수 선택을 지원한다.
2. 동일 필드 선택값은 OR로 처리한다.
3. 서로 다른 필드는 AND로 처리한다.
4. 환적항과 대기구간은 동일한 TS 단계에서 일치해야 한다.
5. 환적항 없이 대기구간만 선택하면 조건을 만족하는 모든 항만을 표시한다.
6. 예정 TS에도 동일한 필터 논리를 적용한다.
7. 필터 전체 초기화를 제공한다.

예: TS1 Singapore 5일, TS2 Rotterdam 22일이면 `Singapore + 21일 이상`에는 조회되지 않고 `Rotterdam + 21일 이상`에만 조회된다.

필터 변경 시 관제 KPI·지도·이벤트·영향물동·조치 큐·시나리오·성과·Export·Agent 범위를 함께 갱신한다.

## 5. 화면 요구사항

### 5.1 공통 UX

| 탭 | 핵심 질문 | 주요 결과 |
|---|---|---|
| 관제 | 지금 어디가 위험한가? | KPI, 지도, 조치 큐 |
| 이벤트 | 왜 위험한가? | TOP5, SOURCE, 영향물동 |
| 시나리오 | 어떻게 대응할 수 있는가? | 대안 비교와 참고 아이디어 |
| 성과 | 위험이 줄었는가? | D-7 대비 오늘 변화 |

- 전체 화면은 흰색 기반 라이트 테마를 사용한다.
- 위험은 색상과 텍스트를 함께 표시한다.
- 실제·예측·데모 상태와 데이터 기준시각을 명시한다.
- 필터와 선택 상태는 탭 이동 후에도 유지한다.
- 데이터가 없으면 0과 결측을 구분해 Empty State를 표시한다.

### 5.2 관제 탭

KPI 카드는 KPI FAIL B/L, Medium·High·Critical B/L, 예정 위험 TS 수와 AIS 신선도를 표시한다. 모든 값은 현재 전역 필터 결과를 사용한다.

글로벌 환적 위험망은 마우스 휠·버튼 확대축소와 드래그 이동을 지원한다. 싱가포르·상해·닝보·파나마는 항상 표시하며, 위험이 없거나 7일 미만이면 초록색, 그 외에는 Medium·High·Critical 색상과 텍스트를 사용한다.

확대 시 필터 Shipment와 연결된 AIS 선박을 표시하고 Shipment, 선박명, MMSI와 최신 위치시각을 제공한다. AIS가 없어도 Shipment를 숨기지 않고 위치 미확인으로 표시한다.

항만 Hover 팝업에는 항만명·코드, 혼잡 상태, 평균·최대 대기일수, 7일 이상 Container·B/L 수, 실제·예정 TS 물량과 Raw Data 전체 보기 버튼을 제공한다.

우선조치 큐에는 Shipment·B/L, 생산법인, TS 순서·항만, 실제·예정 상태, 대기일수·등급, 담당자와 조치상태를 표시한다. 기본 정렬은 대기일수 내림차순이다.

데이터 소스 상태는 AIS, Customs, Route, Carbon, News·Weather·Mail, Kuehne+Nagel myKN News의 상태와 최신 갱신시각을 제공한다.

### 5.3 이벤트 탭

수집 범위는 세계 주요 물류·지정학 뉴스, 공식 기상 경보, 항만·운하 공지, 선사 혼잡·스케줄 메일과 myKN News다.

이벤트 TOP5 순위는 다음 기준으로 산정한다.

1. 현재 필터 물동과 매칭되는 이벤트만 후보에 포함한다.
2. 고유 영향 Container 수 내림차순으로 정렬한다.
3. Container 수가 같으면 신뢰도 내림차순으로 정렬한다.
4. 상위 5건만 표시한다.

각 이벤트는 유형, 제목, 관련 항만, 예상 지연, 신뢰도, 실제·예측 상태와 확인시각을 제공한다. 클릭 시 원문 SOURCE 링크, 출처 유형과 수집시각을 팝업으로 표시한다.

자동 매칭 근거에는 이벤트·TS 항만 일치, 기간 중첩, 항로·권역 연관성과 출처 신뢰도를 포함한다.

영향물동은 고유 Shipment·Container·B/L, 영향 생산법인, 예정 TS 수와 정상·Medium·High·Critical 수·비율로 표시한다. 중량과 TEU는 제외한다.

### 5.4 시나리오 탭

필터 범위에서 가장 위험도가 높고 대기일수가 긴 Shipment를 기본 대상으로 선택한다. 사용자는 B/L, 경로, TS 상태, 관련 이벤트, 목표 ETA와 SLA를 확인한다.

비교 대안은 다음 네 가지다.

1. 현재 경로 유지
2. 대체 환적항과 육상 연결
3. 다음 모선 이용
4. 긴급 항공 전환

비교 지표는 ETA, 지연일수, SLA, 추가 운송비, 회피손실, 잔여 위험, 실행 가능성, 신뢰도와 종합점수다.

시나리오 탭은 센싱 결과를 바탕으로 대응 아이디어를 비교해 보여준다. 별도 상태 변경 단계나 실행상태를 관리하지 않으며 실제 운송을 자동 변경하지 않는다.

### 5.5 성과 탭

- 한국시간 기준 오늘을 D, 7일 전을 D-7로 정의한다.
- 두 날짜를 화면에 표시하고 매일 자동 갱신한다.
- 두 시점에 동일한 전역 필터와 B/L 집계 정책을 적용한다.
- 평균 대기, Critical B/L·비중, KPI FAIL과 SLA FAIL을 비교한다.
- 신규 위험, 위험 유지와 해소 물량을 구분한다.

```text
대기 감소일수 = D-7 평균 대기 - D 평균 대기
Critical 비중 = Critical B/L ÷ 비교 대상 B/L × 100
KPI FAIL 감소 = D-7 KPI FAIL B/L - D KPI FAIL B/L
Critical 해소 = D-7 Critical이고 D에 High 이하인 고유 B/L
```

운송 진행 중은 예측, 완료 후는 실제로 표시한다. D-7 스냅샷이 없으면 비교 불가로 표시한다. 현재 수치는 DEMO DATA이며 운영 전환 후 일별 스냅샷으로 계산한다.

성과 화면은 8주 위험 추세, 항만별 개선 현황과 데이터·자동화 품질도 제공한다.

## 6. Raw Data와 Agent

### 6.1 Excel Export

전체 또는 항만별 XLSX를 제공하며 현재 전역 필터를 반영한다. 항만별 파일에도 선택 Shipment의 모든 TS 단계를 포함한다.

필수 데이터는 기준일, 실제·예측·데모 상태, 생산법인, Shipment·B/L·Container, TS 순서·상태, 환적항 코드·이름, 대기일수·등급, 선박명·MMSI와 전체 운송경로다.

상세 컬럼명, 자료형과 파일 생성 방식은 기술세부문서에서 관리한다.

### 6.2 Agent 역할

| Agent | 역할 | 결과 |
|---|---|---|
| A1 | Shipment·TS 위험 분석 | 위험등급과 우선순위 |
| A2 | 뉴스·기상·메일 감지 | 이벤트 후보와 SOURCE |
| A3 | 이벤트 영향물동 매칭 | Shipment·Container 연결 |
| A4 | 대응 시나리오 추천 | 대안 비교와 추천 근거 |
| A5 | 센싱·보고 반영 | 상태와 성과 요약 |

- Agent는 현재 필터 범위만 처리한다.
- 필터 변경 시 이전 결과를 현재 결과처럼 표시하지 않는다.
- 결과에는 근거, 신뢰도, 실행시각과 실제·합성 상태를 표시한다.
- Agent는 아이디어만 제공하며 실제 조치를 실행하지 않는다.

## 7. 우선순위와 제품 KPI

### 우선순위

Must Have는 TS 단계형 데이터, 위험등급, 전역 필터, 동일 TS 매칭, 예정 Alert, 글로벌 지도, 이벤트 TOP5·SOURCE, 영향물동, 조치 큐, Export와 D-7 성과 비교다.

Should Have는 실제 AIS, 뉴스·기상·메일 자동 수집, 시나리오 아이디어 고도화, 일별 성과 스냅샷, 역할 기반 권한과 감사로그다.

Could Have는 즐겨찾기 필터, Critical 실시간 알림, 과거 AIS 위치 재생과 생산법인별 구독 보고서다.

### 제품 KPI

| KPI | 정의 | 초기 목표 |
|---|---|---:|
| Critical 조기 발견률 | 운영 확인 전에 탐지한 비율 | 80% 이상 |
| 이벤트 자동 매칭률 | 자동 연결된 Shipment 비율 | 70% 이상 |
| 이벤트 매칭 정확도 | 정답 샘플과 일치한 자동 매칭 비율 | 85% 이상 |
| 최초 조치시간 | Alert부터 최초 처리까지 | 4시간 이내 |
| Critical 해소율 | D-7 Critical 중 D에 High 이하인 비율 | 60% 이상 |
| 데이터 신선도 | 기준 시간 내 갱신된 비율 | 95% 이상 |

목표는 실제 운영 데이터 1~3개월 확보 후 재조정한다.

## 8. 비기능 요구사항

### 성능

전역 필터·지도 집계 P95 2초, 이벤트 TOP5 P95 3초, 10만 행 Excel 생성 30초 이하를 목표로 한다.

### 보안과 감사

API 키와 토큰은 서버 Secret으로 관리한다. B/L·Container 마스킹과 Excel 다운로드에 역할 기반 권한을 적용하고 조회·다운로드 이력을 감사로그로 저장한다. 공개 화면에는 실제 물동과 비밀정보를 포함하지 않는다.

### 접근성과 장애 대응

위험은 색상과 텍스트를 함께 사용하고 필터와 주요 버튼은 키보드로 조작할 수 있어야 한다. 데스크톱·모바일에서 핵심 정보가 겹치지 않아야 하며 실제·예측·데모와 0·결측을 구분한다.

외부 API 장애 시 마지막 정상값과 기준시각을 표시한다. AIS 장애가 발생해도 Shipment 원장과 예정 위험 조회를 유지한다.

## 9. 인수 기준

1. 다섯 전역 필터가 모두 복수 선택된다.
2. 동일 필드는 OR, 서로 다른 필드는 AND로 처리된다.
3. 환적항과 대기구간이 같은 TS 단계에서 매칭된다.
4. 환적항 없이 `21일 이상` 선택 시 조건을 만족하는 모든 항만이 표시된다.
5. 예정 TS가 예측값으로 KPI와 Alert에 포함된다.
6. 위험등급별 고유 B/L 합계가 KPI FAIL과 일치한다.
7. 필터 결과가 모든 탭, Export와 Agent에 반영된다.
8. 상시 표시 항만은 위험이 없으면 초록색이다.
9. 지도 확대·축소, 드래그와 항만 Hover가 동작한다.
10. 확대 시 필터 Shipment의 AIS 선박을 확인할 수 있다.
11. 이벤트 TOP5가 Container 수와 신뢰도 기준으로 정렬된다.
12. 이벤트 클릭 시 원문 SOURCE를 확인할 수 있다.
13. 영향물동에서 위험등급별 수와 비율을 확인할 수 있다.
14. Excel에서 Shipment의 모든 TS 단계를 확인할 수 있다.
15. 성과 탭에 한국시간 D-7과 D 날짜가 표시된다.
16. D-7 데이터가 없으면 비교 불가로 표시된다.
17. 실제·예측·데모와 결측 상태가 구분된다.
18. 프로덕션 빌드와 핵심 필터 테스트가 통과한다.
